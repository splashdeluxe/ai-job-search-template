# Contributing

Thanks for wanting to improve this. The template is one person's working system, published so others can run it. Changes that make the system more truthful, safer or easier to run are welcome.

## Before you start

- Open an issue first for anything bigger than a typo. Say which command or rule the change touches, and what happens today.
- Read `AGENTS.md`. The integrity rules there are the product: official boards only, submit exactly once, no invented facts or numbers. A change that loosens one needs a strong reason in the pull request.

## Rules for every change

- No personal data, ever. No real names, emails, salaries, postings you applied to, or tracker rows. Examples follow the fictional Alex Rivera pattern.
- Claims need a source. If the README or a command says the system does something, that behaviour has to exist in a file in this repo.
- Keep the voice. Plain words, short lines, no marketing language. `05-writing-check.md` is the standard every text here is held to.
- One change per pull request. A rule change and a typo fix are two pull requests.

## How to send it

1. Fork or branch, make the change, and work through the pull request template's checklist.
2. If you changed a command, say how you tested it: which step, on what input, and what came out.
3. Expect questions about evidence. That is the review here, not a formality.

## What usually gets declined

- New job boards without a check that they actually work as a feed (see the Glints note in `04-sources.md`).
- Anything that automates around a human-verification check on an application form.
- Features that need the owner's personal accounts or data to work.
